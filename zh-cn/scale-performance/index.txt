# 规模与性能

在决定只用一个渲染器之前，我们测试了 Cytoscape 能否处理 Causal Explorer 的图，它有 725 个节点和 1,494 条边。测量在 Apple M4 Mac 上进行，较旧的设备会慢一些。

| 任务 | 结果 |
| :--- | :--- |
| 缩放和平移，canvas 渲染器 | 60 fps |
| 缩放和平移，WebGL 渲染器 | 56 fps |
| 显示全部 725 个标签时缩放和平移 | 60 fps |
| 使用已保存位置首次渲染 | 118 毫秒 |
| 高亮节点的邻居 | 52 毫秒 |
| 查找强连通分量 | 322 毫秒 |
| 有向介数中心性 | 58 毫秒 |
| 完整 fcose 布局 | 1–4 秒，会阻塞页面 |

因此在这个规模下，canvas 渲染器已经足够，WebGL 选项没有带来提升。请用自己的图测试，因为这些数字取决于所用的样式。

## 不要在页面加载时运行慢布局

完整 fcose 布局会阻塞页面数秒，所以应该计算一次并保存位置：

```ts
import type { LayoutOptions } from "cytoscape";

export const savedLayout = { name: "preset", fit: true, padding: 30 } as LayoutOptions;
```

Explorer 的 `import-data` 脚本在分析时一并完成这一步。请选择在接近正常缩放时能放进屏幕的坐标比例。Explorer 最初的比例大了四倍，初始视图缩得太小，节点几乎看不见。

## 标签需要碰撞处理

Cytoscape 的 `min-zoomed-font-size` 看起来很适合隐藏标签，但密集的图需要更多处理。标签大小随缩放增长，大多数标签几乎同时超过阈值。在 Explorer 中，缩放一步就从少量标签变成全部标签，堆叠得无法阅读。

`keepLabelsReadable` 采用与 Sigma 标签网格相同的思路。在 [`useCausalGraph`](/zh-cn/interactions/) 中启用 `readableLabels` 即可：

1. 按读者正在看的内容给节点排序：先是选中的节点和键盘光标，然后是高亮的回路或路径，再是原因和结果，最后按中心性排序。
2. 有高亮时，被调暗的节点不显示标签。它们只是背景，标签会挤掉真正重要的那些。
3. 依次尝试把标签放在节点的上、下、右、左，取第一个既不遮挡其他标签、也不遮挡其他节点的位置。选中的节点即使没有空位也会保留标签。
4. 文字、文字描边和标签与节点的间距都设为常量除以缩放比例，所以在任何缩放下看起来都一样。连线和箭头的大小同样保持不变，放大时不会变粗。无论线宽多少，Cytoscape 都给箭头设了最小尺寸，所以箭头需要单独缩放。详见[线条、箭头和文字的尺寸](/zh-cn/theming/)。
5. 缩放结束后重新计算（因为每帧更新样式太慢），高亮变化时也会重新计算。

标签用浏览器自己的文字度量来测量，并按 Cytoscape 的方式换行。换行仍可能差一个像素，所以选出的标签还会用 Cytoscape 实际绘制的边界再检查一遍，发生冲突时去掉不太重要的那个。

以前高亮会强制给每个涉及的节点显示标签，完全绕过了上述过程。在 Explorer 中从一个核心事件向外走三步，大约 80 个标签会叠在一起。
