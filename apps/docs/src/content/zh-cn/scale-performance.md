# 规模与性能

在决定只用一个渲染器之前，我们测试了 Cytoscape 能否处理 Causal Explorer 的图，它有 725 个节点和 1,494 条边。测量在 Apple M4 Mac 上进行，较旧的设备会慢一些。

| 任务 | 结果 |
| :--- | :--- |
| 缩放和平移，canvas 渲染器 | 60 fps |
| 缩放和平移，WebGL 渲染器 | 56 fps |
| 显示全部 725 个标签时缩放和平移 | 60 fps |
| 使用已保存位置首次渲染 | 118 毫秒 |
| 高亮节点的邻居 | 52 毫秒 |
| 查找强连通分量 | 322 毫秒 |
| 有向介数中心性 | 58 毫秒 |
| 完整 fcose 布局 | 1–4 秒，会阻塞页面 |

因此在这个规模下，canvas 渲染器已经足够，WebGL 选项没有带来提升。请用自己的图测试，因为这些数字取决于所用的样式。

## 不要在页面加载时运行慢布局

完整 fcose 布局会阻塞页面数秒，所以应该计算一次并保存位置：

```ts
import type { LayoutOptions } from "cytoscape";

export const savedLayout = { name: "preset", fit: true, padding: 30 } as LayoutOptions;
```

Explorer 的 `import-data` 脚本在分析时一并完成这一步。请选择在接近正常缩放时能放进屏幕的坐标比例。Explorer 最初的比例大了四倍，初始视图缩得太小，节点几乎看不见。

## 标签需要碰撞处理

Cytoscape 的 `min-zoomed-font-size` 看起来很适合隐藏标签，但密集的图需要更多处理。标签大小随缩放增长，大多数标签几乎同时超过阈值。在 Explorer 中，缩放一步就从少量标签变成全部标签，堆叠得无法阅读。

`apps/explorer/src/labels.ts` 采用与 Sigma 标签网格相同的思路：

1. 按重要性给节点排序。
2. 依次放置标签，跳过会与已放置标签重叠的标签。
3. 把字体大小设为常量除以缩放比例，让文字始终可读。
4. 只在缩放结束后重新计算，因为每帧更新样式太慢。

标签大小先根据文本长度估算，因为这样很快。换行后的文字无法精确估算，所以选出的标签还要再用 Cytoscape 实际绘制的边界检查一遍。

## 亲眼看结果

标签问题通过了所有测试，包括性能测试。数字没有问题，屏幕却无法阅读。请在多个缩放级别检查截图，并把发现的问题写成测试：Explorer 现在会统计每个缩放级别下重叠的标签。
